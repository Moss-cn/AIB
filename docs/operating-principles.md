# A-Level 评估工具运行原理 v1.0

**配套**：《A-Level AI 视频画质审核定义标准》v1.0（`docs/audit-standard.md`）
**实现**：Python CLI（`alevel/`）+ 浏览器版（`index.html`，Pyodide 驱动）

## 1. 系统架构

```

```

**双引擎一致性保证**：评级引擎（权重/阈值/否决）在 JS 与 Python 各实现一份，
93,750 组评分组合全量比对一致（`web/parity_test.mjs`）。

## 2. 端到端数据流

1. **取帧**：浏览器用 `<video>` + Canvas 抽帧；CLI 用 ffmpeg 管道输出 rawvideo。
   统一采样：10 fps、≤120 帧（浏览器 60）、灰度、宽 ≤256px（浏览器 128）。
2. **指标计算**：五组纯 numpy 算法（见 §3），输出每维度 1–5 分 + 原始指标值 + 置信度。
3. **等级判定**：引擎按标准 §6 计算综合得分、逐级核查阈值、应用一票否决。
4. **报告**：JSON（机器可读）+ Markdown（人读，含等级徽章/维度表/判定过程）。

## 3. 维度指标算法原理

### 3.1 A 有效空间分辨率

**hf_ratio（频域高频能量占比）**

```
对每帧做 2D FFT，|F(u,v)|² 为功率谱; 计算半径 r > 0.25·Rmax 的环形带能量占比
hf_ratio = Σ_{r>0.25Rmax} P(r) / Σ P(r)
```

真实细节（纹理、边缘）产生高频能量；纯色/糊化画面高频占比低。
**注意**：高频能量可被噪声/过度锐化欺骗，故与 res_retention 互补。

**res_retention（降采样-恢复保真度）**

```
帧 → 面积平均降采样 2× → 双线性放大回原尺寸 → 与原帧求 NCC
res_retention = NCC(原帧, 恢复帧)
```

真实细节在缩放往返中能较好保留；AI 的"假细节"（纹理涂抹/过度锐化）在往返中漂移更大。

```
A 分 = clip(0.35·s(hf_ratio) + 0.65·s(res_retention))
```

### 3.2 B 时间稳定性

**flicker（时间域高频能量占比）**

```
1) 逐像素减去时间均值 (去 DC, 避免平均亮度淹没闪烁信号)
2) 沿时间轴 FFT → 功率谱 P_t(k)
3) flicker = Σ_{|k|>0.35·Nyq} P_t(k) / Σ P_t(k)
```

纯交替闪烁（0.8/0.2/0.8...）能量集中在奈奎斯特频率 → 比值≈1；平滑运动能量在低频 → 比值小。

**flow_smooth（光流光滑度）**

```
块匹配光流: 16px 块, 搜索窗 ±8px, 步长 8px (分析宽 ≤160px)
对每帧对求运动场, 计算均值绝对散度
flow_smooth = mean(|∂u/∂x| + |∂v/∂y|)
```

真实运动场平滑；AI 抖动/形变在流场产生尖刺。

```
B 分 = clip(0.6·s(flicker) + 0.4·s(flow_smooth))
```

**已知限制**：快速运动（每帧位移 > 搜索窗）时光流失效（testsrc2 demo 中 B 偏低）。

### 3.3 C 结构完整性

**morphing（运动补偿结构残余）**

```
1) 块匹配光流 (16px 块, 搜索 ±4px) 得到帧间像素位移场
2) 用位移场把 t+1 帧逐像素对齐回 t 帧 (最近邻 warp)
3) 在对齐后帧与原帧的差异上, 按边缘强度加权
morphing = mean(|f_t − warp(f_{t+1})| · edge_w)
```

平滑运动（真实相机/主体）可由光流解释 → 残余低；人脸形变/结构崩坏在运动补偿后仍留高残余。

**face（Haar 人脸增强，cv2 可用时）**

```
检出率 face_rate = 有人脸帧数 / 采样帧数
边框抖动 face_jitter = 相邻帧人脸中心位移均值 / 帧宽

C 分 = clip(0.35·s(morphing) + 0.30·s(face_rate) + 0.35·s(face_jitter))  [检测到人脸时]
C 分 = clip(s(morphing))                                           [无人脸/无 cv2 时]
```

无人脸场景按中性处理，不误伤风景/物体类视频。

### 3.4 D 物理一致性

**light_consistency（主光照方向一致性）**

```
1) Sobel 梯度 → 幅值 m 与方向 θ = atan2(g_y, g_x)
2) 取每帧 top 15% 幅值的强梯度, 计算方向单位向量均值 (vx, vy)
3) 跨帧合成向量长度 R = |mean(v)|  (0..1)
平坦帧 (梯度幅值 85 分位 < 0.02) 跳过 — 无光照信息时不下结论
```

主梯度方向受光照/阴影主导；光源漂移、光影矛盾会使 R 下降。

**luminance_flux（亮度时间稳定性）**

```
luminance_flux = mean_t | mean(f_t) − mean(f_{t+1}) |
```

全局亮度突变（光照跳变/白平衡漂移）→ 通量高。

```
D 分 = clip(0.55·s(light_consistency) + 0.45·s(luminance_flux))
```

**诚实边界**：D 是弱代理（置信度 low）——反射内容匹配、碰撞反应等真实物理一致性暂未覆盖。

### 3.5 E 纹理自然度

**blocking（块效应强度）**

```
对 8px 分块: 块边界梯度均值 / 块内梯度均值, 度量偏离 1 的程度
blocking = mean | g_boundary / g_inside − 1 |
```

压缩伪影与部分 AI 伪影在块边界产生异常梯度。**弱代理**（置信度 low），纹理质感高度主观，
正式审核建议配合人工复核。

### 3.6 标定函数

每个指标原始值经**分段线性映射**到 1–5 分，端点定义在 `spec.CALIBRATION`：

```
s(x) = clip( s0 + (s1−s0)·(x−m0)/(m1−m0), 1, 5 )
```

其中 (m0,s0)/(m1,s1) 为低/高标定点。**当前为占位默认值**，正式发布须按标准 §7.2 重新标定。

## 4. 评级引擎原理

### 4.1 综合得分

```
Composite = (0.20·A + 0.30·B + 0.20·C + 0.15·D + 0.15·E) × 2   (2–10 分制)
Composite =  0.20·A + 0.30·B + 0.20·C + 0.15·D + 0.15·E          (1–5 分制)
```

### 4.2 等级判定

```
从 A10 向下找第一个满足全部要求的等级 (综合分 + 核心项 + 进阶项)
应用一票否决: 等级 = min(判定等级, 否决上限)
```

### 4.3 否决

```
C ≤ 1 或 c_severe → 上限 A2
B ≤ 1 或 b_severe → 上限 A3
```

## 5. 双引擎一致性

- 规则集中在 `spec.py`（Python）与 `web/js_engine.js`（JS），两处数据（权重/阈值/否决/分制）逐一对应。
- 自动化验证：`web/gen_expected.py` 用 Python 引擎生成 93,750 组期望（5 维度整数分 × 进阶/否决变体 × 双分制），
  `web/parity_test.mjs` 用 JS 引擎逐组比对 → 全部一致。
- 浏览器内指标与 CLI 指标共用同一份 Python 源码（构建时内嵌进 `index.html`），结果逐位一致（实测 flicker 视频 5 维度分相同）。

## 6. 标定与扩展

- **重新标定**：改 `spec.CALIBRATION` 的端点 → 重新构建 Web（`python web/build.py`）→ 跑 `tests/run_all.py` 回归。
- **新增指标**：在 `metrics/` 新增模块，实现 `evaluate(frames) -> {dim, score, confidence, metrics, note}`，
  加入 `cli.py` 调用链、`web/build.py` 的 `PY_SOURCES`、并补标定端点与测试。
- **重型探针**：`metrics/adapters.py` 提供 MediaPipe/RAFT/OCR/Depth/ArcFace 骨架，装好依赖即可替换内置代理指标。

## 7. 性能与限制

| 环节 | 指标 |
|------|------|
| CLI 自动评测 | 120 帧 × 256px：约 5–10 秒（块匹配光流为主要耗时） |
| 浏览器（本地 Pyodide） | 60 帧 × 128px：约 0.5–2 秒（lite 模式） |
| 浏览器首次加载 | 下载 Pyodide + NumPy ≈ 15–20MB（宽带 10–30 秒） |

**已知限制**（详见可行性报告）：
1. 快速运动时光流失真（影响 B/C，建议接 RAFT）。
2. D/E 为弱代理指标，仅作参考。
3. 自动指标标定参数为占位值，正式评级前必须重新标定。
4. 灰度帧分析暂不覆盖色彩相关失效模式（色偏、色彩闪烁）。
